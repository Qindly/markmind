# 44. Dashboard 搜索结果虚拟列表冲突修复

## 本次任务做了什么

本次任务修复了 Dashboard 搜索结果与右侧文档列表虚拟化之间的高度冲突问题。

完成之后，只要用户输入了搜索关键字，右侧文档列表就会临时回退为全量渲染；清空搜索后，再恢复原本的虚拟列表启用逻辑。这样可以保留普通大列表下的滚动性能，同时避免搜索摘要出现时的卡片重叠、滚动条长度异常和底部空白错位。

## 涉及的文件清单

- `web/src/features/dashboard/components/DocumentListPanel.tsx`
- `docs/plan.md`
- `docs/44-dashboard-search-virtual-list-fix.md`

## 核心设计决策和原因

- 本次不尝试支持动态高度虚拟列表。
  当前 `useVirtualListWindow` 明确建立在固定行高模型上，而搜索结果卡片会因为摘要和命中标签变成可变高度。如果这次强行加动态高度测量，会明显扩大任务范围。
- 本次不压缩搜索结果卡片高度来迁就虚拟列表。
  搜索结果的摘要和命中来源本来就是为了提升可读性，如果为了维持虚拟化而牺牲展示信息，收益不如直接在搜索模式回退全量渲染稳定。
- 虚拟列表只在普通列表模式启用。
  这样可以继续保留超过 40 条文档时的滚动性能优化，同时让搜索结果走最稳定的渲染路径。

## 前端组件结构和数据流说明

- `DocumentListPanel` 继续作为右侧文档列表的虚拟化入口。
- 当 `searchKeyword` 为空时，组件仍按“加载完成 + 非行内编辑 + 文档数量超过阈值”的规则启用虚拟列表。
- 当 `searchKeyword` 非空时，组件直接跳过 `useVirtualListWindow` 的切片结果，改为渲染完整搜索结果列表。
