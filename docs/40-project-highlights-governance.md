# 40. 项目亮点文档规范补充

## 本次任务做了什么
本次任务补齐了项目亮点总文档和规范约束，把前面新增的 Dashboard 搜索 perf 亮点写入了 `docs/project-highlights.md`，并把已有亮点的一句话总结统一改成了更适合简历表达的结果句式。

同时，在 `AGENTS.md` 中新增了“只要任务产出 perf 或其他项目亮点，就必须同步更新 `docs/project-highlights.md`”的强制规则，并补了一段完整示例，方便后续直接照着写。

## 涉及的文件清单
- `docs/project-highlights.md`
- `AGENTS.md`

## 核心设计决策和原因
- 亮点总文档继续独立于编号任务文档维护。
  这样开发过程记录和对外表达内容可以分层保存，避免每次都从实现复盘里手工摘简历亮点。
- 亮点一句话总结统一改成简历式结果表达。
  这样每条亮点都能更快复用到简历、面试自我介绍和项目介绍里，不需要二次改写。
- 在规则旁边补示例，而不是只写抽象要求。
  明确的示例更容易让后续书写风格保持稳定，也能减少 AI 对“什么叫简历式表达”的自由发挥空间。

## 已知 TODO / 待改进项
- 后续如果再产出新的 perf、稳定性、工程化或安全性亮点，需要继续按新规则补写到 `docs/project-highlights.md`。
- 当前亮点文档仍以简洁结果表达为主，更细的实现过程和设计取舍依旧以各自编号任务文档为准。
