# 06-project-wide-encoding-cleanup

## 本次任务做了什么

在上一轮服务端源码乱码修复的基础上，继续清理整个项目中剩余的历史乱码，覆盖环境示例文件、鉴权加固文档、API 文档以及前端鉴权状态恢复相关注释。

## 涉及文件清单

- `.env.example`
- `docs/03-auth-hardening.md`
- `docs/api.md`
- `web/src/hooks/useAuthBootstrap.ts`
- `web/src/stores/authStore.ts`

## 核心设计决策和原因

1. 直接按 UTF-8 重写受影响文件
   - PowerShell 在部分写入链路下会把中文吞成问号，因此本轮直接使用 Node 以 UTF-8 重写文件内容。
   - 这样可以确保注释、标题、错误说明和示例文本都恢复为可读中文。

2. 文档按当前实现状态同步更新
   - `docs/api.md` 不只修复乱码，还顺手按照当前鉴权接口行为重新整理了请求参数、返回样例与限流说明。
   - `docs/03-auth-hardening.md` 同步反映目前的 `.env` / `.env.example`、限流、代理与会话恢复策略。

3. 前端只修正文案，不改运行逻辑
   - `useAuthBootstrap` 与 `authStore` 的会话恢复和持久化逻辑保持不变。
   - 本次只恢复文件头注释与函数说明，避免影响现有行为。

## 验证说明

- 使用 UTF-8 脚本重新读取相关文件，确认中文内容恢复正常。
- 额外扫描项目中的注释与 Markdown 行，确认不再存在 `???` 或被吞成问号的乱码段落。
- 因为本次修改了前端源码文件，后续已按项目规矩执行前端构建校验与 Docker 构建校验。

## 已知 TODO / 待改进项

- 如果后续继续通过 PowerShell 批量写入中文文件，建议统一走 UTF-8 友好的脚本链路，避免再次引入问号乱码。
- 当前项目内的中文内容已完成可见范围清理，后续新增文件仍应保持 UTF-8 编码保存。
